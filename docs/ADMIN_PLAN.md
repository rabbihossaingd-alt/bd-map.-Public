## ২. বড় সিদ্ধান্ত

1. **স্ট্যাক:** vanilla JS থাকবে, কোনো ফ্রেমওয়ার্ক বা বিল্ড ধাপ যোগ হবে না। প্যানেল ভাগ হবে ES modules-এ (`admin/shell.js`, `admin/ui/*.js`, `admin/pages/*.js`), প্রতিটা পাতা `import()` দিয়ে দরকার হলে লোড হবে। চার্ট নিজে লেখা হালকা SVG — লাইব্রেরি লাগবে না। ফন্ট: Anek Bangla (আছে) + Inter (Google Fonts থেকে, শুধু সংখ্যা/ইংরেজির জন্য)।
2. **নতুন API `/api/admin/v2/*`**, আলাদা ফাইল `lib/admin-v2.cjs`-এ (server.js আর বড় হবে না)। পুরনো `/api/admin/*` পুরো migration শেষ না হওয়া পর্যন্ত চালু থাকবে, পুরনো প্যানেল `admin-old.html` নামে থাকবে।
3. **প্রতিটা পরিবর্তনকারী v2 এন্ডপয়েন্ট একই পাইপলাইনে:** অনুমতি চেক → ইনপুট যাচাই → SQLite transaction-এ কাজ + audit লেখা → SSE ইভেন্ট। এটা একটা `defineAction({ perm, validate, run })` হেল্পার দিয়ে বাধ্যতামূলক হবে, যাতে কোনো এন্ডপয়েন্ট খতিয়ান বাদ দিতে না পারে।
4. **অ্যাডমিন সেশন আলাদা:** অ্যাপে লগইন থাকলেও প্যানেল খুলতে একবার "elevation" লাগবে (TOTP, না থাকলে ই-মেইল কোড)। এতে একটা আলাদা কুকি `mz_admin` (`HttpOnly; Secure; SameSite=Strict; Path=/api/admin`), ৩০ মিনিট নিষ্ক্রিয়তায় লক, সর্বোচ্চ ১২ ঘণ্টা। স্তর ৩ কাজে আবার কোড (১০ মিনিট বৈধ)।

## ৩. স্কিমা migration

সব migration `ALTER TABLE ... ADD COLUMN` / `CREATE TABLE IF NOT EXISTS` — বিদ্যমান ডেটা মোছা বা বদলানো হবে না। rollback: নতুন টেবিল/কলাম পুরনো কোড উপেক্ষা করে, তাই পুরনো ভার্সনে ফিরে গেলেও চলবে (প্রতিটা migration-এর পাশে `-- rollback:` নোট থাকবে)। প্রতিটা migration-এর আগে R2-তে ডাটাবেসের কপি নিশ্চিত করা হবে।

## ৫. স্পেকের যেসব জায়গা আমাদের সিস্টেমের সাথে মেলে না (সৎ নোট)

1. **মিডিয়া পাইপলাইন:** ভিডিও সার্ভারে ট্রান্সকোড হয় না — ফোনেই ছোট হয়ে (WebCodecs) আসে, সার্ভারে কোনো জব-কিউ নেই। তাই এই পাতা দেখাবে: আপলোড (আকার, রেজোলিউশন, ছোট করা হয়েছিল কিনা), R2-তে কপি হয়েছে কিনা (`r2_files`, `r2_public`), R2-র মোট আকার ও আনুমানিক খরচ, ১০০ MB-এর বড় বা ছোট-না-করা ফাইল, আর R2-তে না-যাওয়া ফাইলের "আবার চেষ্টা"। "ট্রান্সকোড জব" থাকবে না।
2. **ডিভাইসের শহর ও লিংকড অ্যাকাউন্ট:** আমাদের কাছে আছে শুধু ব্রাউজার/ডিভাইসের বিবরণ আর IP। শহর জানতে বাইরের IP-লোকেশন সার্ভিসে IP পাঠাতে হবে — **প্রস্তাব: শহর দেখাব না।** "একই ডিভাইসে অন্য অ্যাকাউন্ট" হবে IP + ডিভাইস-বিবরণের মিল দিয়ে, আর একে "সম্ভাব্য" হিসেবেই দেখানো হবে (একই ওয়াই-ফাইয়ে অনেকে থাকে)।
3. **DAU/WAU/MAU, রিটেনশন, ফিচার ব্যবহার, সার্চ ইনসাইট:** এখন দৈনিক কার্যক্রমের ইতিহাস রাখা হয় না (শুধু "শেষ সক্রিয়")। চালু করার দিন থেকে গোনা শুরু হবে; প্রথম কয়েক সপ্তাহ চার্ট অসম্পূর্ণ থাকবে, প্যানেলে তা লেখা থাকবে।
4. **ঢাকার বাস রুট এডিট:** রুটগুলো এখন একটা স্ট্যাটিক ফাইল (`data/dhaka-buses.js`, `tools/build-buses.py` থেকে বানানো)। প্যানেল থেকে এডিট মানে: পরিবর্তন DB-তে (`route_edits`, ভার্সনসহ) রাখা, আর অ্যাপ লোডের সময় সেগুলো মূল ফাইলের উপর বসানো। এটা ফেজ ৩-এর সবচেয়ে বড় কাজ।
5. **আপিল, সীমিত করা, স্ট্রাইকের নোটিশ:** ব্যবহারকারীর দিকেও অ্যাপে UI লাগবে ("আপনার পোস্ট সরানো হয়েছে — কারণ… · আপিল করুন")। এটা মূল অ্যাপের পরিবর্তন, ফেজ ৪-এ।
6. **পুশ নোটিফিকেশন ব্রডকাস্ট:** পুশ ব্যবস্থা আছে — ব্রডকাস্ট এর উপরেই হবে। "জেলা অনুযায়ী" টার্গেট করতে ব্যবহারকারীর জেলা জানা লাগবে, যা এখন রাখা হয় না; প্রস্তাব: প্রথমে সবাই / ক্রিয়েটর / ভাষা অনুযায়ী।
7. **মোছার ৩০ দিনের গ্রেস:** শুধু অ্যাডমিন যখন মোছেন তখন। ব্যবহারকারী নিজে অ্যাকাউন্ট মুছলে এখনকার মতো সঙ্গে সঙ্গে মুছবে (Play Store/App Store-এর শর্ত আর আমাদের প্রাইভেসি পলিসি তাই বলে)।
8. **কিল-সুইচ (রিড-অনলি মোড):** সার্ভারে সব লেখার রিকোয়েস্টে একটা চেক বসবে; অ্যাডমিন API বাদে সব POST 503 পাবে আর অ্যাপ একটা বার্তা দেখাবে। সম্ভব, তবে মূল অ্যাপে ছোট পরিবর্তন লাগবে।
9. **PII মাস্ক:** ব্যবহারকারী ই-মেইল দিয়ে লগইন করেন, ফোন নম্বর রাখা হয় না — মাস্ক হবে ই-মেইল ও ওয়ালেট নম্বরে।
10. **CSRF:** এখন JSON content-type চেক আর `SameSite` দিয়ে আটকানো আছে। v2-তে এর সাথে প্রতিটা POST-এ `X-CSRF` হেডার টোকেন যোগ হবে।

| প্যানেল বড় হয়ে ফোনে ধীর | শেল + কমান্ড সেন্টার প্রথমে; বাকি `import()`; এগ্রিগেট ৫ মিনিট ক্যাশ |
| SSE-তে মূল অ্যাপের স্ট্রিমে চাপ | অ্যাডমিন স্ট্রিম আলাদা (`/api/admin/v2/stream`), শুধু টিমের জন্য |
| একসাথে দুই অ্যাডমিন একই কাজ | `case_assignments` লক + "রাহিম দেখছেন" ইন্ডিকেটর; সার্ভারে ইডেম্পোটেন্সি কী |
